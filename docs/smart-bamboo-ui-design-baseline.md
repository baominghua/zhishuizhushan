# 智慧竹山 UI 设计基线

本文用于约束智慧竹山综合管理平台后续前端和后台界面迭代。当前判断来自 `impeccable` 的 product UI 规则，并结合 `taste skill` 的反模板检查；`taste skill` 不直接用于后台数据表和复杂产品 UI，只作为避免模板感、避免装饰过度的辅助标准。

## 设计读法

这是公共林业/GIS 运营管理产品，不是营销站。核心用户是政府管理者、企业运营者、林业数据人员和项目实施团队。界面应当让 100 万亩竹山数据查得快、筛得动、改得稳、权限边界清楚。

## 后台浅色台账

- 后台默认使用浅色主题，保持 `admin.css` 的 `color-scheme: light` 和完整设计 token。
- 主体信息页以台账为第一屏，不把查询、新增、编辑混在同一个常驻表单里。
- 每个独立模块采用列表、详情、编辑、新建、删除的标准 CRUD 结构。
- 台账行最右侧固定操作栏，提供行级查看、编辑、删除；查看不需要管理权限，编辑和删除按模块动作权限控制。
- 详情和编辑使用独立面板或浮层，不占用台账主宽度。
- 空态必须写明数据来源，例如“暂无后台数据”“请先在管理台账中新增或导入”，不展示固定演示数字。

## 权限与菜单

- 左侧菜单对应独立后台页面，便于后续按角色配置功能权限。
- 左侧菜单必须按业务域分组；在权限 API 未返回前也要有静态菜单分组兜底。
- 角色权限管理必须区分菜单入口权限、动作权限、导出权限和数据范围。
- 页面按钮、行级操作、导出入口必须带明确权限码；公开只读大屏摘要接口不伪装成后台权限码。
- 权限目录、部署诊断和上线清单要能追踪核心接口是否存在。

## 大屏与移动端

- 大屏只做展示、筛选、定位和业务入口，不直接维护业务数据。
- 大屏业务指标、列表、碳汇、卫星图传、搜索结果都以后台 API 为准。
- API 无数据时显示“暂无后台数据”一类真实空态，不回退到固定假数据。
- 前端地图筛选围绕林班编号、区县乡村、基地类型、经营类型、风险等级和图层发布状态展开。

## 视觉规则

- 后台使用克制绿色作为主操作和选中态，不用深色大屏风格套后台。
- 表格、筛选器、按钮、状态标签、详情字段保持统一尺寸和圆角。
- 不使用装饰性玻璃拟态、强渐变文字、过度阴影、无意义动画。
- 文本不随视口缩放，长字段允许换行或压缩，不得溢出按钮、表格单元格或详情面板。
- 加载、空态、错误、禁用、无权限状态都要有可读文案和稳定布局。

## 后续执行

新增或改造任何后台模块时，先按此基线检查：

1. 是否是独立页面和独立权限边界。
2. 是否以台账作为主体。
3. 是否有行级查看、编辑、删除。
4. 是否有真实后台 API 与空态。
5. 是否保持后台浅色台账风格。
6. 是否通过相关 JS 语法检查和 pytest 回归。

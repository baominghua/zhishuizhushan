# 智慧竹山移动端 UI 与原生客户端路线图

## 技术结论

移动端采用“共享业务内核、独立移动交互、双端轻原生壳”的结构：

- 共享现有 FastAPI 接口、权限、任务状态机、审计、幂等键和离线同步协议，不建设平行台账。
- React/TypeScript 继续承载巡护、劳务、安全、轨迹、凭证和同步队列，但 `/v2/field/mobile` 使用独立移动界面，不加载后台侧栏与桌面顶栏。
- Android 与 iOS 只承载系统能力：相机、后台定位、通知、文件选择、安全存储、网络状态和应用更新；业务页面与规则仍由共享移动 Web 更新。
- GIS、点云和三维模型不放入首屏常驻加载。现场任务按需打开轻量二维地图或独立影像窗口，避免占用低端手机内存。

## 已实施的移动 Web 首版

- 独立全屏现场工作面，桌面后台壳不再重复出现。
- “今日现场”优先展示逾期任务、本机任务、待同步记录及离线包更新时间。
- 44px 以上触控目标、清晰的任务状态层级、底部任务/同步/同步记录导航。
- 保留 IndexedDB 凭证暂存、8MB 分片续传、轨迹采集、幂等同步和冲突转后台确认。
- 任务详情在手机端以底部抽屉呈现，减少页面跳转，保留拍照、视频和现场上报。

## 共同桥接协议

原生壳向 Web 暴露版本化能力对象，不直接写业务数据库：

- `camera.capture`：照片/短视频采集，返回本地文件引用。
- `location.start/stop/status`：轨迹采集及权限状态。
- `network.status`：网络类型和计费状态。
- `notification.register`：推送令牌注册。
- `secureStore.get/set/remove`：短期会话与设备绑定信息。
- `file.pick/share/download`：现场文件与离线包处理。

所有桥接调用携带请求号，返回成功、取消、拒绝、超时四类结果；Web 无原生桥接时自动退回浏览器能力。

## 迭代顺序

1. 先在生产环境验证移动 Web 首版和现有离线同步。
2. 修正 Android 壳的地址、缓存、文件和定位能力，发内部 APK。
3. 固化跨端桥接协议，同时建立 iOS WKWebView 原型。
4. 接入推送、后台定位、安全存储和设备治理。
5. 完成 Android 灰度与 iOS TestFlight，再评估是否需要将高频原生模块改为 Kotlin/Swift 页面。

# 智慧竹山 V2 信息架构与权限方案

## 1. 设计目标

V2 后台从“菜单驱动的数据库管理”升级为“岗位驱动的运营工作台”。用户先看到自己需要处理的事情，再进入专业台账查数据；管理人员仍可通过独立模块配置权限和维护主数据。

## 4. 标准页面模式

### 4.1 主数据台账

适用于林班、林权、主体、人员、设备、模型等对象。

- 顶部：标题、数据口径、刷新、新增、导入、导出。
- 筛选：默认展示常用条件，高级筛选折叠。
- 主体：全宽列表，右侧固定查看、编辑、删除操作栏。
- 详情：独立抽屉或详情页，包含基础信息、关联对象、附件、时间轴。
- 编辑：独立表单，关联林班、林权、主体时从正式台账检索选择。

### 4.2 业务办理页

适用于巡护、采伐、事件、工单和无人机任务。

- 左侧或顶部显示业务摘要和当前状态。
- 中部显示当前办理表单、地图和证据。
- 右侧显示责任人、时限、相关对象和下一步动作。
- 历史流程收纳在时间轴，不把审计字段铺满主页面。
- 页面只提供当前角色可执行的动作，不同时展示所有状态按钮。

### 4.3 GIS 工作台

- 地图占据主要视口，顶部提供统一搜索、区域定位、筛选入口和常用工具。
- 筛选面板默认隐藏，从顶部“筛选”按钮展开，已生效条件显示为可移除标签。
- 左侧只保留图层、搜索结果和专题切换，不堆叠复杂表单。
- 点击图斑进入对象摘要，可继续查看档案、任务、事件和影像。
- 大数据量使用聚合和瓦片，不一次加载全部几何。

## 6. 权限模型

权限由四层共同决定：

1. 菜单权限：能否进入模块。
2. 操作权限：查看、创建、编辑、删除、审核、导入、导出、发布等动作。
3. 数据范围：本人、本部门及下级、指定行政区、指定林场、全部。
4. 字段与资源权限：证件号、电话、工资、视频、林权附件等敏感内容。

权限码统一采用 `{domain}.{resource}.{action}`，例如：

- `resource.blocks.view`
- `resource.blocks.update`
- `resource.rights.attach`
- `operations.patrol.assign`
- `operations.harvest.approve`
- `safety.incidents.command`
- `iot.devices.remoteControl`
- `system.audit.export`

## 7. 交互简化规则

1. 普通用户不进入“审计流”，只在详情时间轴查看必要记录。
2. 同一操作只保留一个主按钮，后续动作由当前状态决定。
3. 无异常的数据接入允许一键入库；有异常时只处理异常项。
4. 关联林班、林权、主体、人员和设备必须使用搜索选择器，不允许自由输入正式编号。
5. 删除默认进入回收站；重要记录只允许作废，不提供删除。
6. 空态明确下一步行动，例如“尚无林班，请先导入测绘成果”。
7. 错误提示同时说明原因和可执行的修复方法。
8. 所有长任务进入后台队列，页面显示进度并允许离开，不让浏览器持续转圈。

## 8. 响应式边界

- PC 运营端面向 1440px 及以上设计，并保证 1280px 可完整办理。
- 平板用于地图核查和现场管理，复杂系统配置仍在 PC 完成。
- 手机端只呈现任务、轨迹、上报、消息和应急能力，不压缩桌面后台到小屏幕。

# 南平市智慧竹山综合运营平台 V2 开发总方案

版本：V2.0 方案基线
日期：2026-08-04
依据：《南平市智慧竹山综合运营平台需求规格说明书 20260804》及现有 V1 代码、数据库和部署能力。

## 1. 建设结论

V2 不再以“继续增加后台菜单”为建设方式，而是重构为一套围绕空间资源、任务事件和角色工作台运行的综合运营平台：

- 一个空间资源底座：行政区划、林班、小班、林权、影像、道路和设备位置使用统一标识与空间参考。
- 一条运营主线：发现风险或业务需求后，统一经过事件、任务、处置、验收和归档。
- 三个用户端：PC 运营端、移动作业端、领导指挥端。
- 四个业务中心：资源数据中心、生产运营中心、安全应急中心、AI 与设备中心。

## 2. 建设原则

1. 业务闭环优先于页面数量，所有功能必须有责任人、状态、时限、证据和结果。
2. 林班是空间锚点，林权是法律凭证，经营主体是权责主体，任务事件是业务主线，四者独立建模并建立关系。
3. 台账用于查询和管理，工作台用于办理业务，驾驶舱用于分析，不把三种用途混在同一页面。
4. 前端不保存真实业务口径，不使用固定演示数字；指标必须可追溯到明细记录。
5. 复杂审批、采伐、安全、劳务和设备告警使用专用状态机，通用 JSON 表单只服务简单档案和配置项。
6. V2 采用模块化单体架构，优先解决数据一致性和业务闭环，暂不为形式拆分微服务。
7. 软件、数据生产、AI 模型、硬件接入和安全性能分别立项、分别验收。

## 3. 产品组成

| 产品面 | 核心职责 | 主要用户 |
| --- | --- | --- |
| 综合运营工作台 | 待办、任务、事件、预警、跨模块办理 | 政府监管、运营管理、技术运维 |
| GIS 一张图 | 资源查询、分层筛选、空间分析、变化核查 | 资源管理、巡护、采伐、领导 |
| 生产运营中心 | 巡护、管护、采伐、劳务、经营服务 | 生产管理、合作社、企业 |
| 安全应急中心 | 告警、SOS、处置、调度、复盘 | 安全管理、指挥人员 |
| AI 与设备中心 | 模型、无人机、IoT、安全帽、媒体资产 | 技术运维、设备管理 |
| 移动作业端 | 接单、导航、轨迹、离线上报、音视频证据 | 一线作业人员、巡护员 |
| 领导驾驶舱 | 专题指标、趋势、风险和业务钻取 | 领导、指挥人员 |

## 4. V1 继承与重构

### 4.1 直接继承

- 林班、林权、图档关联、成果导入、遥感影像和地图图层能力。
- 用户名密码登录、组织角色、菜单权限、操作权限、数据字典和行政区划。
- MySQL 正式存储、对象文件目录、GeoServer、Nginx 和双主机人工容灾部署。
- 后台浅色台账、独立页面、行级查看编辑删除和真实空态规范。

### 4.2 需要重构

- 将 `business_records` 限定为主数据和轻量配置，不继续承载采伐、劳务、安全等核心交易。
- 将“成果入库审核流”简化为上传解析、异常确认、正式入库三步；技术审计流水移入批次详情。
- 将长菜单首页改为按角色组织的工作台，菜单仍保留为权限边界和专业台账入口。
- 将大屏业务卡片改为可钻取指标，明确统计口径、更新时间和数据责任人。
- 将移动端从 WebView 展示壳升级为支持离线任务、轨迹、媒体上传和冲突处理的作业应用。

## 5. 交付文档

本方案由以下文档共同构成：

1. `smart-bamboo-v2-scope-baseline.md`：范围、边界、优先级和非目标。
2. `smart-bamboo-v2-domain-model.md`：核心实体、关系、状态机和数据规则。
3. `smart-bamboo-v2-information-architecture.md`：角色工作台、页面清单和权限体系。
4. `smart-bamboo-v2-technical-architecture.md`：前后端、GIS、数据、设备和迁移方案。
5. `smart-bamboo-v2-roadmap-and-acceptance.md`：阶段任务、团队、验收和风险控制。

## 7. 启动门槛

进入代码开发前必须完成以下基线评审：

- V2.0 交付范围和明确不做项获得确认。
- 林班、小班、林权、主体、任务、事件的统一编码规则冻结。
- 三条首批闭环流程完成原型：成果入库、巡护事件、采伐监管。
- 角色数据范围和关键操作权限矩阵完成确认。
- MySQL 到 PostgreSQL/PostGIS 的迁移策略完成演练设计。
- AI、无人机、安全帽供应商提供可测试协议、设备、样本和责任边界。

## 8. 推荐启动顺序

第一轮开发只启动 V2.0 底座和 V2.1 一张图，不同时铺开全部十个模块。首个可验收版本必须先证明：真实数据可以导入、查找、筛选、关联、派发任务、现场反馈并形成可追溯结果。

## 9. 当前实施进度

截至 2026-08-10，V2 资源底座已完成以下可运行能力：

- `/api/v2`、V2 React 运营端、角色菜单和操作权限骨架已建立。
- 林班台账沿用正式空间主数据；小班台账已作为独立领域实体落地，不再混入林班或林权档案表。
- 小班必须选择现有林班作为父级空间单元，自动继承县、乡镇、村级区划；资源调查、立地条件、经营状态和空间边界由小班独立维护。
- 小班已具备 JSON、MySQL、PostgreSQL/PostGIS 兼容存储路径，支持列表筛选、详情、新增、编辑、软删除、版本快照和并发版本校验。
- V2 运营端已提供独立“小班台账”菜单和路由，采用全宽台账、行级查看/编辑/删除、侧边详情与独立表单交互。
- 新权限 `forest.subcompartments.view/create/update/delete/manage` 已进入权限目录；为避免越权，不自动授予既有业务角色，由管理员在角色权限配置中显式启用。

小班台账已完成后端、契约和前端结构测试，并通过生产构建及浏览器增、查、改、软删除回归。资源调查与历史版本也已形成正式闭环：调查批次独立管理、关联正式小班、快照每次修改自动留痕、跨期指标自动对比、完成归档使用独立权限且归档后不可重开。下一项按 V2.1 顺序建设“统一附件中心与调查证据关联”，供资源调查、巡护、采伐、安全和无人机成果统一复用。
